# DR-0004: cwd からの相対パスを std に渡す経路と、その作り方

- Status: Accepted
- Date: 2026-11-18

## Context

ソケットのパスが cwd の近くにあれば、cwd からの相対パスは `sun_path` に収まりうる。相対パスは文字列で書き直すだけで、cwd を変えずに使える。ただし symlink を含むパスや `$PWD` の嘘があると、書かれたままの比較では同じ場所を指さない綴りができる。

## Decision

元のパスが絶対パスで、相対パスが std にそのまま渡せる長さ ([DR-0002](DR-0002-std-handles-paths-it-accepts.md)) なら、それを std に渡す。パスを文字列で書き直すだけで、cwd は変えない。

相対パスは 2 つの作り方を、この順に試す。

1. **cwd の下にあるなら、前を削る。** パスが cwd の綴りで始まっていれば (区切り単位で比べる。`/a/b` は `/a/bc` の接頭辞ではない)、それを削った残りを使う
   - cwd の綴りの候補は `getcwd(3)` の値と `$PWD`
   - `$PWD` は `stat($PWD)` と `stat(".")` の `(st_dev, st_ino)` が一致した時だけ使う。`getcwd` の値はそのまま使う
2. **1 で std にそのまま渡せる長さにならない時だけ、両方を実パスに揃えて `..` で上る。** ソケットのディレクトリを `realpath(3)` で実パスにし、`getcwd` の実パス (macOS で `cd /var` すると `/private/var` が返る) との差から、`..` で上ってから下る綴りを作る

2 つのうち短い方を使う。

- 使う前に、相対パスのディレクトリと元のディレクトリの `(st_dev, st_ino)` が同じことを確かめる (cwd が消されている、他のスレッドが変えた、を弾く)
- bind / connect の後に cwd の `(st_dev, st_ino)` が変わっていないことを確かめ、変わっていたら結果を捨ててエラー (`Other`) にする (試験は bind / connect を行う関数の中で cwd を変えて、他のスレッドの代わりにする)
- 事後確認で弾いた bind が作ったソケットファイルは消さない
- 元のパスが相対パスの時は、この経路は使わない
- 保証の範囲は「bind / connect の間に cwd を変えないプロセス」で、doc にそう書く
- macOS ではこの綴りを広げた sockaddr でも使う ([DR-0005](DR-0005-widened-sockaddr-on-macos.md))

## 理由

- 1 の残りは cwd から下へ降りるだけで、元のパスと同じ symlink を同じ順に通るので、解決の結果が元のパスと一致する。realpath も要らない
- `$PWD` は環境変数なので嘘をつきうる (`chdir` が更新しない、誰でも書ける)。なので stat で照合する
- 2 は両方が実パスなので、どの `..` も実ディレクトリから上り、カーネルの解決と一致する。パスの途中の symlink の先で `..` を使うと、symlink の先の親に着いてしまう
- cwd はプロセスの全スレッドで共有される。他のスレッドが途中で `chdir` すると別のディレクトリで bind / connect したことになる。事後確認で見えるのは、その間に cwd が変わったままの場合だけで、変えて戻した場合は見えない
- 弾いた bind のソケットファイルは、どこにできたかが分からないので、消そうとすると別のファイルを消しうる
- 元のパスが相対パスなら、それ自体が cwd 基準で、短くする手が無い

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 相対パスを書かれたままのパスの比較だけで作る | `/var` と `/private/var` のように片方が symlink 経由だと共通部分を見落とし、短くならない。cwd の接頭辞を削る手 (区切り単位、`$PWD` は stat で照合) と、実パスに揃える手の 2 段で作る |
