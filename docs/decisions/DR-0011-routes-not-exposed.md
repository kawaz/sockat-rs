# DR-0011: どの経路を通ったかは利用者に見せず、試験は crate 内で各経路を強制する

- Status: Accepted
- Date: 2026-11-18

## Context

経路は OS と環境 (/proc の有無、`TMPDIR`、カーネルが広げた sockaddr を受け付けるか) で決まる。試験では各経路を確実に通したいが、そのための口を公開 API に出すと利用者の面が増える。

## Decision

- 経路 (`Route`) は crate 内の値で、公開 API は捨てる。`connect_any` 系が返すのは経路の名前でなく、fork の経路を通ったか (= サーバに見える peer の pid が終了したプロセスのものになったか) だけ ([DR-0010](DR-0010-public-api.md))
- 試験は crate 内の単体試験 (`src/tests.rs`) に置き、各経路の関数を直接呼んで強制する
- 経路の順番の分岐は、環境を読む部分を値 (`route::posix::Config`) にして試験から差し替える
  - symlink の置き場の候補
  - macOS で広げた sockaddr を受け付けないカーネル
  - Linux の /proc の場所 (`/proc/self/fd`。試験は何も無い場所や空のディレクトリを渡して /proc の無い環境の代わりにし、本物の /proc には触らない)
- feature も cfg(test) 専用の公開口も作らない

## 理由

- 利用者が知る必要が無い。利用者に関係するのは fork の副作用が乗ったかだけで、それは `bool` で返す
- 試験は crate 内で足りる

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 経路を公開 API で返す / 強制する feature を作る | 利用者が知る必要が無い。試験は crate 内で足りる |
